---

## What LandGrant is

Attorney-in-the-loop eminent domain / right-of-way platform:

- FastAPI backend (`backend/app/`, 194 routes) on Cloud Run, Celery
  workers on Cloud Run, PostgreSQL 16 + PostGIS on Cloud SQL, Redis
  on Memorystore, evidence on GCS, Vertex AI Gemini 1.5 Flash for
  drafting/summarization (never decisions).
- Vite + React SPA (`frontend/`) for six personas: `landowner`,
  `land_agent`, `in_house_counsel`, `outside_counsel`, `firm_admin`,
  `admin`.
- Terraform IaC under `infra/gcp/` (Cloud Run services, Cloud SQL,
  Memorystore, Secret Manager, GCS, IAM, dashboards, scheduled jobs).
- Versioned YAML rule packs per jurisdiction under `rules/` and
  MD/DOCX templates under `templates/`.

Full architecture detail: [`docs/architecture.md`](./architecture.md).

## Known issues — not blockers, but must be scheduled

### 1. Pre-existing test-isolation leaks in the full backend suite

`pytest` without filters still hangs during `tests/test_endpoints_rbac.py`
when it runs after the earlier agent / workflow / template suites.
Each suite passes cleanly in isolation (proven by the targeted runs
above), so the root cause is shared global state (DB connections +
FastAPI dependency overrides + cached Gemini/VertexAI clients) not
being torn down between modules. **This predates this review pass**
and is tracked as follow-up `QA-1` below. Until it's fixed, CI must
run by file or by marker rather than a bare `pytest`.

### 2. Local Python is 3.9.6 instead of 3.11

The project pins 3.11 (`backend/.python-version`, Dockerfiles). The
dev venv on this machine is 3.9 and fires a wall of
`google-auth` / `pydantic` deprecation warnings. Tests still pass
because the code is 3.9-compatible, but CI and prod must stay on
3.11. Tracked as `INFRA-2`.

### 3. `landright` → `landgrant` rename is repo-only

All Terraform resource **logical IDs** were renamed. Deployed GCP
resources still use the old names. Re-applying the current plan
against the existing project will destroy and recreate the Cloud
Run services, the Cloud SQL instance, and the GCS buckets. Tracked
as `INFRA-1` with required migration steps:

1. Stand up the renamed stack in a fresh GCP project (green).
2. Snapshot Cloud SQL + copy GCS, replay into green.
3. DNS cutover `app.landgrantiq.com` / `api.landgrantiq.com` to
   green.
4. Decommission the `landright-*` project after an agreed
   watch-period.

### 4. Deferred P4 component splits

`api.ts`, `CopilotPanel`, `TaskManager`, `DocumentExtraction`,
`LitigationPanel`, `AdminPage`, and `ParcelMap` are all over the
"one-screen-of-editor" threshold set in
`docs/testing-strategy.md`. They are functionally correct today —
the split is a maintainability investment, not a defect — and I
elected not to do it in this pass so the higher-priority security
and correctness work would land atomically. Tracked as `FE-REFACTOR-*`.
